# 요구사항 분석과 UML

## 요구사항의 분류
기능 요구사항은 시스템이 무엇을 하는지, 어떤 기능을 제공해야 하는지에 관한 요구사항이다. 예를 들어 "회원은 주문 내역을 조회할 수 있어야 한다"는 기능 요구사항이다.
비기능 요구사항은 시스템이 기능을 얼마나 잘 수행하는지에 관한 요구사항으로, 성능, 보안, 가용성, 사용성, 호환성 같은 품질과 제약 조건을 다룬다. "검색 결과는 2초 안에 표시되어야 한다"는 비기능 요구사항이다.

## 요구사항 개발 프로세스
요구사항 개발은 도출, 분석, 명세, 확인(검증) 순서로 진행한다.
도출은 이해관계자에게서 요구사항을 수집하는 단계로 인터뷰, 설문, 브레인스토밍, 프로토타이핑, 유스케이스 같은 기법을 쓴다.
분석은 수집한 요구사항의 모호함과 충돌을 찾아 정리하는 단계이고, 명세는 분석한 요구사항을 문서로 기술하는 단계다.
확인은 명세된 요구사항이 이해관계자의 의도와 맞는지, 빠진 것은 없는지 검토하는 단계다.

## 요구사항 분석 기법
자료 흐름도(DFD)는 시스템 안에서 데이터가 어떻게 흐르고 변환되는지를 프로세스, 데이터 흐름, 자료 저장소, 단말(외부 엔터티) 네 가지 기호로 표현한다.
자료 사전(DD)은 자료 흐름도에 나오는 데이터의 이름과 구성을 정의한 사전이다. 자료 사전에서 = 는 정의, + 는 연결, [ ] 는 선택, { } 는 반복, ( ) 는 생략 가능, * * 는 주석을 뜻한다.
HIPO는 시스템의 기능을 입력, 처리, 출력 관계로 나타내는 하향식 설계 도구로, 가시적 도표, 총체적 도표, 세부적 도표로 구성된다.

## UML 개요
UML은 시스템을 시각적으로 모델링하기 위한 표준 언어로, 사물, 관계, 다이어그램으로 구성된다.
구조 다이어그램은 시스템의 정적인 구조를 표현하며 클래스, 객체, 컴포넌트, 배치, 복합체 구조, 패키지 다이어그램이 있다.
행위 다이어그램은 시스템의 동적인 동작을 표현하며 유스케이스, 시퀀스, 커뮤니케이션, 상태, 활동, 상호작용 개요, 타이밍 다이어그램이 있다.

## UML 관계
연관 관계는 사물 사이에 서로 연결되어 있음을 나타낸다.
집합(집약) 관계는 전체와 부분의 관계지만 부분이 전체와 독립적으로 존재할 수 있는 관계로, 속이 빈 마름모로 표시한다.
포함(합성) 관계는 부분이 전체에 완전히 종속되어 전체가 사라지면 부분도 함께 사라지는 관계로, 속이 채워진 마름모로 표시한다.
일반화 관계는 상위 개념과 하위 개념, 즉 상속 관계를 나타낸다.
의존 관계는 한 사물이 다른 사물을 잠깐 사용하는 짧은 관계로, 점선 화살표로 표시한다.
실체화 관계는 인터페이스와 그 기능을 구현한 클래스의 관계다.

## 유스케이스 다이어그램
유스케이스 다이어그램은 사용자 관점에서 시스템이 제공하는 기능을 액터와 유스케이스로 표현한다.
포함(include) 관계는 어떤 유스케이스를 실행할 때 다른 유스케이스가 반드시 함께 실행되는 관계다. 예를 들어 "주문하기"를 하려면 항상 "로그인"이 필요하다.
확장(extend) 관계는 특정 조건을 만족할 때만 다른 유스케이스가 추가로 실행되는 관계다. 예를 들어 "주문하기" 중 쿠폰이 있을 때만 "쿠폰 적용"이 실행된다.

## 시퀀스 다이어그램
시퀀스 다이어그램은 객체들이 주고받는 메시지를 시간 순서에 따라 표현한다. 구성 요소는 액터, 객체, 생명선, 실행 상자(활성 상자), 메시지다. 생명선은 객체가 존재하는 기간을 세로 점선으로 나타낸다.
