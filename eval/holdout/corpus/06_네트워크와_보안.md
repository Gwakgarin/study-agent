# 네트워크와 보안

## OSI 7계층
물리 계층은 전기적 신호로 비트를 전송한다. 리피터와 허브가 이 계층에서 동작한다.
데이터 링크 계층은 인접한 노드 사이에서 프레임을 오류 없이 전달하며 MAC 주소를 사용한다. 브리지와 스위치가 이 계층에서 동작한다.
네트워크 계층은 패킷이 목적지까지 갈 경로를 정하는 라우팅을 담당하며 IP 주소를 사용한다. 라우터가 이 계층에서 동작한다.
전송 계층은 종단 간(End-to-End) 신뢰성 있는 데이터 전송을 담당하며 TCP와 UDP가 있다.
세션 계층은 통신하는 두 시스템 사이의 연결(세션)을 설정하고 유지하며 동기화한다.
표현 계층은 데이터의 형식 변환, 암호화, 압축을 담당한다.
응용 계층은 사용자가 네트워크에 접근하는 서비스를 제공하며 HTTP, FTP, SMTP, DNS 같은 프로토콜이 있다.

## TCP와 UDP
TCP는 연결 지향 프로토콜로, 3-way 핸드셰이크(SYN, SYN-ACK, ACK)로 연결을 맺은 뒤 데이터를 보낸다. 순서 보장, 오류 제어, 흐름 제어, 혼잡 제어를 제공해 신뢰성이 높다.
UDP는 비연결형 프로토콜로, 연결 설정 없이 데이터를 보내며 순서와 도착을 보장하지 않는다. 대신 빠르고 헤더가 단순해 실시간 스트리밍이나 DNS 조회에 쓴다.

## IP 주소
IPv4는 32비트 주소로, 8비트씩 4부분으로 나눠 점으로 구분한 10진수로 표기한다.
IPv6는 128비트 주소로, 16비트씩 8부분으로 나눠 콜론으로 구분한 16진수로 표기한다. 주소 공간이 매우 넓고, 유니캐스트, 멀티캐스트, 애니캐스트 주소를 쓴다. IPv6에는 브로드캐스트 주소가 없다.
서브넷 마스크는 IP 주소에서 네트워크 부분과 호스트 부분을 구분한다. 예를 들어 /24 는 앞의 24비트가 네트워크 부분이라는 뜻이며, 이 네트워크에서 쓸 수 있는 호스트 주소는 네트워크 주소와 브로드캐스트 주소를 뺀 254개다.

## 암호화
대칭키(비밀키) 암호화는 암호화와 복호화에 같은 키를 쓴다. 속도가 빠르지만 키를 안전하게 나눠 갖는 것이 어렵다. DES, AES, SEED, ARIA가 있다.
비대칭키(공개키) 암호화는 암호화에 쓰는 공개키와 복호화에 쓰는 개인키가 다르다. 키 분배가 쉽지만 속도가 느리다. RSA가 대표적이며, RSA는 큰 수의 소인수분해가 어렵다는 점에 기반한다.
해시 함수는 임의 길이의 입력을 고정 길이의 값으로 바꾸는 일방향 함수로, 원래 값으로 되돌릴 수 없다. 데이터 무결성 확인과 비밀번호 저장에 쓰며 SHA, MD5가 있다. 비밀번호를 저장할 때는 같은 비밀번호라도 다른 해시가 나오도록 솔트를 덧붙인다.

## 보안의 3요소
기밀성은 인가된 사용자만 정보에 접근할 수 있게 하는 것, 무결성은 인가된 사용자만 정보를 수정할 수 있게 하는 것, 가용성은 인가된 사용자가 필요할 때 언제든 정보를 사용할 수 있게 하는 것이다.

## 공격 기법
SQL 인젝션은 입력 값에 SQL 구문을 끼워 넣어 데이터베이스를 조작하거나 정보를 빼내는 공격이다. 입력값 검증과 매개변수화된 쿼리(Prepared Statement)로 막는다.
XSS(크로스 사이트 스크립팅)는 게시판 같은 웹 페이지에 악성 스크립트를 심어, 그 페이지를 본 다른 사용자의 브라우저에서 스크립트가 실행되게 하는 공격이다.
CSRF는 로그인한 사용자가 자신의 의도와 상관없이 공격자가 노린 요청(글쓰기, 송금 등)을 서버에 보내게 만드는 공격이다.
DoS는 대량의 요청으로 서버 자원을 고갈시켜 정상적인 서비스를 못 하게 하는 공격이고, 여러 대의 감염된 컴퓨터를 동원하면 DDoS다. SYN 플러딩은 TCP 연결 요청(SYN)만 대량으로 보내고 응답을 마무리하지 않아 서버의 연결 대기열을 가득 채우는 공격이다.
스니핑은 네트워크에 흐르는 패킷을 몰래 엿보는 소극적 공격이고, 스푸핑은 IP 주소나 MAC 주소 등을 속여 다른 시스템인 척하는 공격이다.

## 접근 통제
임의적 접근 통제(DAC)는 데이터 소유자가 다른 사용자에게 접근 권한을 줄 수 있는 방식이다.
강제적 접근 통제(MAC)는 시스템이 주체의 보안 등급과 객체의 비밀 등급을 비교해 접근을 결정하는 방식이다.
역할 기반 접근 통제(RBAC)는 사용자에게 직접 권한을 주는 대신 역할에 권한을 주고, 사용자에게 역할을 부여하는 방식이다.
