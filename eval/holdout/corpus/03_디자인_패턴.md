# 객체지향 설계와 디자인 패턴

## 객체지향 설계 원칙 (SOLID)
단일 책임 원칙(SRP)은 하나의 클래스는 하나의 책임만 가져야 한다는 원칙이다.
개방-폐쇄 원칙(OCP)은 소프트웨어 요소가 확장에는 열려 있고 변경에는 닫혀 있어야 한다는 원칙이다. 기존 코드를 고치지 않고 새 기능을 추가할 수 있어야 한다.
리스코프 치환 원칙(LSP)은 자식 클래스가 언제나 부모 클래스를 대체할 수 있어야 한다는 원칙이다.
인터페이스 분리 원칙(ISP)은 클라이언트가 자신이 사용하지 않는 메서드에 의존하지 않도록 인터페이스를 작게 나눠야 한다는 원칙이다.
의존 역전 원칙(DIP)은 상위 모듈이 하위 모듈의 구체적인 구현이 아니라 추상화에 의존해야 한다는 원칙이다.

## 결합도와 응집도
좋은 설계는 모듈 간 결합도는 낮추고 모듈 내부의 응집도는 높인다.
결합도는 모듈 사이의 상호 의존 정도로, 약한 것부터 자료 결합도, 스탬프 결합도, 제어 결합도, 외부 결합도, 공통 결합도, 내용 결합도 순이다. 자료 결합도는 모듈 간에 단순한 값만 주고받는 가장 바람직한 결합이고, 내용 결합도는 한 모듈이 다른 모듈의 내부 기능이나 자료를 직접 참조하는 가장 나쁜 결합이다.
스탬프 결합도는 배열이나 레코드 같은 자료 구조를 통째로 주고받을 때, 제어 결합도는 다른 모듈의 처리 흐름을 바꾸는 제어 신호(플래그)를 넘길 때 생긴다. 공통 결합도는 여러 모듈이 공유하는 전역 변수를 함께 참조할 때 생긴다.
응집도는 모듈 안 구성 요소들이 서로 관련된 정도로, 강한 것부터 기능적, 순차적, 교환(통신)적, 절차적, 시간적, 논리적, 우연적 응집도 순이다. 기능적 응집도는 모듈 안의 모든 요소가 하나의 기능을 위해 존재하는 가장 바람직한 응집이다.

## 디자인 패턴 분류
GoF 디자인 패턴은 목적에 따라 생성 패턴 5개, 구조 패턴 7개, 행위 패턴 11개, 모두 23개로 분류된다.

## 생성 패턴
싱글톤 패턴은 클래스의 인스턴스가 오직 하나만 생성되도록 보장하고, 어디서든 그 인스턴스에 접근할 수 있게 한다. 설정 관리자나 커넥션 풀처럼 하나만 있어야 하는 객체에 쓴다.
팩토리 메서드 패턴은 객체를 만드는 인터페이스는 상위 클래스에 두고, 어떤 클래스의 인스턴스를 만들지는 하위 클래스가 결정하게 한다.
추상 팩토리 패턴은 서로 관련된 객체들의 묶음을 구체적인 클래스를 지정하지 않고 생성한다.
빌더 패턴은 복잡한 객체를 만드는 과정을 단계별로 나눠, 같은 생성 절차로 서로 다른 표현의 객체를 만들 수 있게 한다.
프로토타입 패턴은 원본 객체를 복제해서 새 객체를 만든다.

## 구조 패턴
어댑터 패턴은 호환되지 않는 인터페이스를 가진 클래스를 클라이언트가 기대하는 인터페이스로 변환해 함께 쓸 수 있게 한다. 기존 라이브러리를 새 시스템에 붙일 때 쓴다.
데코레이터 패턴은 객체에 기능을 동적으로 덧붙인다. 상속 대신 객체를 감싸는 방식으로 기능을 확장한다.
프록시 패턴은 실제 객체 대신 대리 객체를 두어 접근을 제어한다. 무거운 객체를 필요할 때만 불러오거나 접근 권한을 검사할 때 쓴다.
퍼사드 패턴은 복잡한 서브시스템 앞에 단순한 통합 인터페이스를 하나 제공한다.
컴포지트 패턴은 객체들을 트리 구조로 묶어 개별 객체와 복합 객체를 같은 방식으로 다루게 한다.
그 밖의 구조 패턴으로 브리지, 플라이웨이트가 있다.

## 행위 패턴
옵저버 패턴은 한 객체의 상태가 바뀌면 그 객체에 의존하는 다른 객체들에게 자동으로 알림이 가도록 한다. 구독과 알림 구조로 이벤트 처리에 쓴다.
전략 패턴은 같은 문제를 푸는 여러 알고리즘을 각각 캡슐화하고, 실행 중에 알고리즘을 바꿔 끼울 수 있게 한다.
템플릿 메서드 패턴은 상위 클래스에 알고리즘의 뼈대를 정의하고, 세부 단계는 하위 클래스에서 구현하게 한다.
커맨드 패턴은 요청을 객체로 캡슐화해 실행 취소나 요청 기록이 가능하게 한다.
이터레이터 패턴은 컬렉션의 내부 구조를 드러내지 않고 요소에 차례로 접근하는 방법을 제공한다.
