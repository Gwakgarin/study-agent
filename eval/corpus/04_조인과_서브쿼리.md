# 조인, 서브쿼리, 집합 연산

## 조인의 종류
EQUI JOIN은 두 테이블의 컬럼 값이 정확히 일치하는 경우에 사용하는 조인으로, 주로 기본키와 외래키 관계를 기반으로 한다. NON EQUI JOIN은 BETWEEN이나 크다, 작다 같은 = 이외의 연산자로 조인하는 방식이다.
INNER JOIN은 조인 조건을 만족하는 행만 반환한다.
NATURAL JOIN은 두 테이블에서 이름이 같은 모든 컬럼으로 EQUI JOIN을 수행한다. NATURAL JOIN에 사용된 컬럼에는 테이블 별칭(접두사)을 붙일 수 없다.
USING 조건절은 이름이 같은 컬럼 중 원하는 컬럼만 골라 EQUI JOIN을 하며, 이 경우에도 USING에 사용된 컬럼에는 접두사를 붙일 수 없다.
CROSS JOIN은 조인 조건 없이 두 테이블의 모든 행을 조합하는 카티션 곱을 반환한다. A 테이블이 3행, B 테이블이 4행이면 결과는 12행이다.

## OUTER JOIN
LEFT OUTER JOIN은 왼쪽 테이블의 모든 행을 반환하고, 오른쪽 테이블에 일치하는 행이 없으면 NULL로 채운다. RIGHT OUTER JOIN은 그 반대다. FULL OUTER JOIN은 양쪽 테이블의 모든 행을 반환하며, LEFT와 RIGHT OUTER JOIN 결과의 합집합에서 중복을 제거한 것과 같다.
Oracle에서는 조인 조건에서 데이터가 없는 쪽 컬럼에 (+) 기호를 붙여 OUTER JOIN을 표현할 수 있다.

## 계층형 질의
계층형 질의는 테이블에 계층형 데이터가 있을 때 사용한다. Oracle에서는 START WITH로 루트 데이터를 지정하고 CONNECT BY로 부모와 자식 관계를 지정한다. PRIOR 자식 = 부모 형태로 쓰면 부모에서 자식 방향으로 내려가는 순방향 전개가 된다.
LEVEL 가상 컬럼은 루트가 1이고 하위로 내려갈수록 1씩 증가한다. CONNECT_BY_ISLEAF는 리프 데이터면 1, 아니면 0을 반환한다. ORDER SIBLINGS BY는 같은 레벨의 형제 노드 사이에서 정렬한다.

## 서브쿼리
서브쿼리는 하나의 SQL 문 안에 포함된 또 다른 SQL 문이다. 서브쿼리는 괄호로 감싸야 한다.
단일행 서브쿼리는 결과가 한 행만 반환되며 =, <, > 같은 단일행 비교 연산자와 함께 쓴다. 다중행 서브쿼리는 여러 행을 반환하며 IN, ALL, ANY, SOME, EXISTS 같은 다중행 비교 연산자와 함께 써야 한다.
연관 서브쿼리(Correlated Subquery)는 서브쿼리가 메인쿼리의 컬럼을 참조하는 서브쿼리다. 메인쿼리의 행마다 서브쿼리가 다시 수행된다.
EXISTS는 서브쿼리의 결과가 한 행이라도 존재하는지만 확인하며, 조건을 만족하는 행을 찾으면 더 이상 탐색하지 않는다.
SELECT 절에 쓰는 서브쿼리를 스칼라 서브쿼리라고 하며, 반드시 한 행 한 컬럼만 반환해야 한다. FROM 절에 쓰는 서브쿼리를 인라인 뷰라고 한다.

## 뷰
뷰는 실제 데이터를 갖지 않는 가상 테이블로, 뷰 정의만 저장된다. 뷰의 장점은 독립성, 편리성, 보안성이다. 테이블 구조가 바뀌어도 뷰를 사용하는 애플리케이션은 변경하지 않아도 되고, 복잡한 질의를 단순하게 작성할 수 있으며, 숨기고 싶은 컬럼을 빼고 뷰를 만들어 정보를 감출 수 있다.

## 집합 연산자
UNION은 여러 쿼리 결과의 합집합을 구하고 중복 행을 제거한다. 중복 제거를 위해 정렬 작업이 일어날 수 있다.
UNION ALL은 중복을 제거하지 않고 결과를 그대로 합친다. 정렬이 필요 없어 UNION보다 빠르다.
INTERSECT는 교집합을, EXCEPT(Oracle에서는 MINUS)는 차집합을 구한다.
집합 연산을 할 때 각 SELECT 문의 컬럼 수와 데이터 타입이 같아야 한다. 결과의 컬럼 이름은 첫 번째 SELECT 문의 컬럼 이름을 따른다. ORDER BY는 마지막 SELECT 문 뒤에 한 번만 쓸 수 있다.
