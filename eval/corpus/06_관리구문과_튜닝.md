# 관리 구문과 SQL 최적화

## DCL과 권한
GRANT는 사용자에게 권한을 부여하고 REVOKE는 권한을 회수한다. WITH GRANT OPTION으로 부여받은 사용자는 다른 사용자에게 그 권한을 다시 부여할 수 있으며, 원래 권한을 회수하면 연쇄적으로 회수된다. WITH ADMIN OPTION은 시스템 권한에 사용하며, 권한을 회수해도 그 사용자가 부여한 권한은 연쇄적으로 회수되지 않는다.
ROLE은 여러 권한을 묶어 놓은 집합으로, 많은 사용자에게 같은 권한을 부여할 때 관리를 쉽게 해준다. CONNECT는 접속 권한, RESOURCE는 객체 생성 권한을 묶은 대표적인 롤이다.

## MERGE
MERGE 문은 대상 테이블에 조건에 맞는 데이터가 있으면 UPDATE하고, 없으면 INSERT한다. WHEN MATCHED THEN과 WHEN NOT MATCHED THEN 절로 분기한다.

## 옵티마이저
옵티마이저는 SQL을 가장 효율적으로 수행할 수 있는 실행 계획을 찾아주는 DBMS의 핵심 엔진이다.
규칙 기반 옵티마이저(RBO)는 미리 정해진 우선순위 규칙에 따라 실행 계획을 결정한다. 규칙 기반 옵티마이저에서 가장 높은 우선순위는 ROWID를 사용한 단일 행 접근이고, 가장 낮은 우선순위는 전체 테이블 스캔이다.
비용 기반 옵티마이저(CBO)는 테이블과 인덱스의 통계 정보를 바탕으로 예상 비용이 가장 적은 실행 계획을 선택한다. 통계 정보가 부정확하면 잘못된 실행 계획이 선택될 수 있다. 현재 대부분의 DBMS는 비용 기반 옵티마이저를 사용한다.
실행 계획은 SQL을 실행하기 위한 절차와 방법을 표현한 것으로, 조인 순서, 조인 기법, 액세스 기법, 최적화 정보, 연산 등으로 구성된다. 실행 계획이 달라도 SQL의 실행 결과는 같다.

## 인덱스
인덱스는 원하는 데이터를 빠르게 찾기 위해 키 값과 위치 정보(ROWID)를 정렬해 저장한 구조다. 인덱스를 사용하면 조회 성능은 좋아지지만 INSERT, UPDATE, DELETE 같은 DML 작업 시에는 인덱스도 함께 변경해야 하므로 성능이 저하된다.
B-트리 인덱스는 가장 일반적인 인덱스로, 루트 블록, 브랜치 블록, 리프 블록으로 구성된다. 리프 블록에는 키 값과 ROWID가 저장되며, 리프 블록끼리는 양방향 링크로 연결되어 범위 검색에 유리하다. 일치 검색과 범위 검색 모두에 적합하다.
비트맵 인덱스는 성별처럼 값의 종류가 적은 컬럼에 적합하며 주로 데이터 웨어하우스에서 사용된다.
SQL Server의 클러스터형 인덱스는 리프 페이지에 실제 데이터 페이지가 있어 인덱스 순서와 데이터 저장 순서가 같다. 테이블당 하나만 만들 수 있다.
인덱스 컬럼을 변형하면 인덱스를 사용할 수 없다. 예를 들어 WHERE 절에서 인덱스 컬럼에 함수를 적용하거나, 연산을 하거나, 묵시적 형변환이 일어나면 인덱스 범위 스캔을 할 수 없다. 부정형 비교(<>)나 LIKE '%문자' 같은 앞쪽 와일드카드 조건, IS NULL 조건도 인덱스를 제대로 활용하지 못한다.
결합 인덱스는 여러 컬럼으로 만든 인덱스로, 첫 번째 컬럼이 조건절에 없으면 일반적인 인덱스 범위 스캔을 할 수 없다. 따라서 자주 쓰이고 등치(=) 조건으로 검색되는 컬럼을 앞에 두는 것이 좋다.
전체 테이블 스캔은 테이블의 모든 블록을 읽는 방식으로, 결과 데이터가 테이블의 대부분일 때는 인덱스보다 오히려 유리하다. 전체 테이블 스캔은 한 번에 여러 블록을 읽는 멀티블록 I/O를 사용한다.

## 조인 수행 원리
Nested Loop Join(NL 조인)은 선행 테이블의 행마다 후행 테이블을 반복 탐색하는 방식이다. 랜덤 액세스 위주이므로 처리 범위가 좁을 때 유리하며, 후행 테이블의 조인 컬럼에 인덱스가 있어야 효율적이다. 결과를 가능한 한 빨리 화면에 보여줘야 하는 온라인 프로그램에 적합하다.
Sort Merge Join은 두 테이블을 조인 컬럼 기준으로 각각 정렬한 뒤 병합하는 방식이다. 조인 컬럼에 인덱스가 없어도 되고, 비동등 조인에도 사용할 수 있다. 정렬할 데이터가 많으면 임시 영역을 사용해 성능이 떨어질 수 있다.
Hash Join은 작은 테이블(선행 테이블, Build Input)로 해시 테이블을 만들고, 큰 테이블을 읽으며 해시 함수로 조인하는 방식이다. 동등 조인(=)에서만 사용할 수 있으며, 대용량 데이터를 처리할 때 유리하다. 선행 테이블이 작을수록 유리하다.
