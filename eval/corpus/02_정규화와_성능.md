# 정규화와 데이터 모델 성능

## 정규화
정규화는 데이터의 중복을 제거하고 이상 현상을 방지하기 위해 테이블을 분해하는 과정이다. 이상 현상에는 삽입 이상, 갱신 이상, 삭제 이상이 있다.
삽입 이상은 불필요한 데이터를 함께 입력해야만 원하는 데이터를 저장할 수 있는 현상이다. 갱신 이상은 중복된 데이터 중 일부만 수정되어 데이터가 불일치하는 현상이다. 삭제 이상은 어떤 데이터를 삭제할 때 유지해야 할 다른 데이터까지 함께 삭제되는 현상이다.

제1정규형은 모든 속성이 원자값을 가지도록 하는 것이다. 하나의 속성에 여러 값이 들어가는 다중값 속성이나 반복 그룹을 제거한다.
제2정규형은 제1정규형을 만족하면서 부분 함수 종속을 제거한 상태다. 부분 함수 종속은 복합 주식별자의 일부 속성에만 종속되는 일반 속성이 있는 경우를 말한다.
제3정규형은 제2정규형을 만족하면서 이행 함수 종속을 제거한 상태다. 이행 함수 종속은 A가 B를 결정하고 B가 C를 결정할 때 A가 C를 간접적으로 결정하는 관계다. 즉 일반 속성이 다른 일반 속성에 종속되는 경우를 제거한다.
BCNF는 모든 결정자가 후보키가 되도록 하는 정규형이다.
제4정규형은 다치 종속을 제거하고, 제5정규형은 조인 종속을 제거한다.

정규화를 하면 일반적으로 입력, 수정, 삭제 성능은 향상되지만 조회 시에는 조인이 많아져 성능이 저하될 수 있다. 다만 정규화를 통해 테이블이 작아지고 인덱스 효율이 좋아져 조회 성능이 오히려 향상되는 경우도 있다.

## 반정규화
반정규화는 조회 성능을 향상시키기 위해 데이터 중복을 허용하거나 테이블을 통합, 분할하는 기법이다. 비정규화 또는 역정규화라고도 한다.
반정규화를 하면 데이터 무결성이 깨질 위험이 있으므로 먼저 뷰, 클러스터링, 인덱스 조정, 파티셔닝, 애플리케이션 처리 같은 다른 방법을 검토한 뒤 마지막에 적용하는 것이 원칙이다.
반정규화 절차는 반정규화 대상 조사, 다른 방법 유도 검토, 반정규화 적용 순서로 진행한다. 대상 조사에서는 범위 처리 빈도, 대량의 범위 처리, 통계성 프로세스, 테이블 조인 개수를 검토한다.

테이블 반정규화 기법에는 1:1 관계 테이블 병합, 1:M 관계 테이블 병합, 슈퍼타입과 서브타입 테이블 병합 같은 테이블 병합과, 수직 분할과 수평 분할 같은 테이블 분할, 그리고 중복 테이블 추가, 통계 테이블 추가, 이력 테이블 추가, 부분 테이블 추가가 있다.
컬럼 반정규화 기법에는 중복 컬럼 추가, 파생 컬럼 추가, 이력 테이블 컬럼 추가, PK에 의한 컬럼 추가, 응용 시스템 오작동을 위한 컬럼 추가가 있다.
관계 반정규화는 중복 관계를 추가하는 것으로, 여러 경로를 거쳐 조인할 수 있지만 성능 저하를 막기 위해 추가적인 관계를 맺는 방법이다. 관계 반정규화는 무결성을 깨뜨리지 않으면서 성능을 향상시킬 수 있다.

## 슈퍼타입과 서브타입 변환
슈퍼타입/서브타입 모델을 물리 테이블로 변환하는 방법에는 세 가지가 있다.
OneToOne Type은 슈퍼타입과 서브타입을 각각 개별 테이블로 구성하는 방법으로, 조인이 많이 발생한다.
Plus Type은 슈퍼타입과 각 서브타입을 합쳐 서브타입마다 하나의 테이블을 만드는 방법으로, 서브타입별 처리가 많을 때 유리하다.
Single Type 또는 All in One Type은 슈퍼타입과 서브타입을 하나의 테이블로 통합하는 방법으로, 전체를 함께 처리하는 경우가 많을 때 유리하다.

## 분산 데이터베이스
분산 데이터베이스는 여러 곳에 분산된 데이터베이스를 하나의 가상 시스템처럼 사용할 수 있게 한 데이터베이스다.
분산 데이터베이스의 투명성에는 분할 투명성, 위치 투명성, 지역 사상 투명성, 중복 투명성, 장애 투명성, 병행 투명성이 있다. 위치 투명성은 사용하려는 데이터의 저장 장소를 사용자가 알 필요가 없다는 의미다. 중복 투명성은 데이터가 여러 사이트에 중복되어 있어도 사용자는 그 사실을 알 필요가 없다는 것이다.

## NULL 속성과 Row Chaining
Row Chaining은 로우 길이가 너무 길어서 데이터 블록 하나에 데이터가 모두 저장되지 않고 두 개 이상의 블록에 걸쳐 저장되는 현상이다. Row Migration은 데이터 블록에서 수정이 발생하면 수정된 데이터를 해당 블록에 저장하지 못하고 다른 블록의 빈 공간을 찾아 저장하는 현상이다. 두 현상 모두 여러 블록을 읽어야 하므로 I/O가 증가해 성능이 저하된다. 컬럼이 많은 테이블은 자주 쓰는 컬럼과 그렇지 않은 컬럼을 수직 분할하여 이를 줄일 수 있다.
